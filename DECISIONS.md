## 2026-06-10: Precompile semantics adopted from NVNM_MCP_Server; discovery phase narrowed to experiments
Known from the sibling project (ABI vendored at abi/anchoring.json): addRecord takes a 10-field tuple of plain strings and the module does no content validation, so plaintext citations fit in the checksum field natively; records(registry, checksum, recordId, index, pagination) supports keyed reads by registry name + checksum string; the registry creator becomes its admin; grantRole(registryId, checksum, account, role) grants admin/editor at record, registry, or global scope; the precompile emits no events. The genuinely unknown behaviors are Phase 0 experiments (a) through (i) in IMPLEMENTATION_PLAN.md.

## 2026-06-10: Lookup design: keyed chain read AND local index (the draft's options A and B, both)
Receipt-time checks use the direct records() eth_call so a receipt can claim a chain read at a stated block height. Drafting-time checks use the local SQLite index only (no RPC, no trace). The index is rebuildable from chain by anyone with an RPC URL (rebuild-index command), which is the public-auditability claim made executable.

## 2026-06-10: Record schema draft (locks at Phase 1 task 1.5)
Per-case record: checksum = canonical citation plaintext, checksumAlgo = "cite-canonical-v1", uri = CourtListener cluster URL, metadata = compact JSON {name, year, cluster}. Receipts (registry receipts-v1): checksum = document SHA-256, checksumAlgo = "sha256", metadata = full receipt JSON. Registry names = courts-db IDs prefixed "us-". Canonical citation key = the reporters-db EDITION string (F.3d, not F.) with the FIRST-PAGE rule: interior/pin pages are never keys. The first-page rule is load-bearing: the fake Varghese cite (925 F.3d 1339) falls on an interior page of a real case (J.D. v. Azar, 925 F.3d 1291, D.C. Cir.), and first-page keying is why it still returns NOT_FOUND.

## 2026-06-10: Status enum: five statuses plus an orthogonal name_check field
VERIFIED / NOT_FOUND / NOT_COVERED / AMBIGUOUS_JURISDICTION / UNPARSEABLE. NOT_COVERED is new versus the draft: a cite that parses and maps to a court with no on-chain registry (for example a ca2 cite during the scotus+ca11 pilot). Without it, out-of-corpus cites would falsely smell fabricated, and receipts would over-claim. Per-result field name_check: match | mismatch | unknown, a fuzzy compare of the brief's party names against the registry record's case name. It catches the other Mata failure mode (a real citation paired with an invented case name) while staying inside the existence-only invariant: it reports what the registry metadata says the citation denotes, nothing about holdings. It is a field, not a status, because existence and name-pairing are different dimensions and name matching is heuristic.

## 2026-06-10: Task 0.7 experiment matrix results (Phase 0 close; testnet registry dev-probe id 733)
Raw runs: scripts/phase0_experiments.py (quick / throughput / post) plus targeted follow-up probes; ~0.97 wmantraUSD total Phase 0 spend; all measured on nvnm-testnet-1 (787111). Conclusions were adversarially audited against the raw outputs before this entry was written.

(a) **Duplicates VERSION, never reject.** Re-anchoring the same (registry, checksum) succeeds, keeps recordId, bumps index (observed to index=4); isLatest moves to the newest; keyed reads and list views return only the latest version. eth_estimateGas does NOT reject duplicates, so there is no free idempotency probe. SUPERSEDES the bootstrap entry's "one local source says the precompile rejects duplicates (mainnet experience, May 2026)". Loader consequence (task 2.4 amended): the checkpoint DB is the only idempotency guard; never blind-resubmit.

(b) **String caps and required fields, measured.** metadata max 2048 B, uri max 2048 B, checksum max 64 B (each rejection names its limit). uri, checksumAlgo, and metadata are all REQUIRED non-empty, and metadata "{}" is rejected as empty (an empty JSON object counts as empty). SUPERSEDES the bootstrap entry's "the module does no content validation". Gas below the caps: ~76 gas per metadata byte + ~77k fixed (256 B -> 96,219; 1,024 B -> 154,692; 1,024 B confirmed on chain and read back intact). Plaintext multi-word checksums with spaces and periods are accepted, so the citation-in-checksum design stands; canonical citations fit the 64 B cap with huge margin, and a bare sha256 HEX digest fits it exactly (64 chars, zero room for suffixes; base64 form is 44 chars if suffixed keys are ever needed). CONSEQUENCE: a full receipt JSON cannot live in one record's metadata; the chunked/compact receipt design is now required, not a fallback (tasks 4.2/4.3 amended).

(c) **Registry names are UNIQUE**: duplicate addRegistry rejected at estimation ("registry already exists with this name"). Name-keyed lookups are unambiguous and the estimate-probe is a free idempotency check for registry creation.

(d) **Write auth is deny-by-default; grantRole works.** A never-granted address gets "unauthorized"; after grantRole(733, addr, "editor") (41,775 gas, confirmed on chain) the identical calldata estimates cleanly from that address. Deny/allow evidence is at the eth_estimateGas simulation level (unfunded throwaway keys); the Phase 2 multi-key load will exercise it with funded sends. The third-party-attestor invariant is validated, and multi-key parallel loading is possible.

(e) **Single-sender throughput plateaus at ~1.1 tx/s**: 0.29 / 0.73 / 1.11 / 1.13 tx/s at pipeline depths 1 / 5 / 20 / 50 with contiguous nonces (no mempool pushback). Nonce-GAPPED submission is REJECTED outright ("tx nonce: 270, account accountNonce: 269"), so per-key submission must be strictly serialized in nonce order, a failed send halts everything queued behind it, and recovery means re-sending the same nonce. ~95k records per key per day. Phase 2 plans parallel editor-granted keys; whether the plateau is per-sender or global resolves during the multi-key load.

(f) **updateRecordStatus**: absent from the vendored ABI; nvnm-tutorial (May 2026) reported it missing from the deployed binary; not probeable without its authoritative signature. Correction policy: supersede-by-new-version (proven viable by (a)), with revocation expressed in the superseding version's metadata.

(g) **Pagination**: the server caps every page at exactly 200 rows (limit=300 and limit=10000 both returned 200 of the 264 present); nextKey is never populated; countTotal returned 0 on every query shape, which closes the 0.6 entry's "pending the (g) experiment" caveat: totals are unreliable everywhere and must be counted client-side. Full sync = OFFSET-based paging until a short page. List views show only the latest version per record. Re-verify the 200 cap at Phase 2 scale.

(h) **The public RPC is a full archive node**: balances served at block 1 and every depth tried, and a direct bidirectional observation at the registry's creation boundary (absent at block 1,573,400; present, id 733, at 1,573,510). Pinned-block receipt re-verification works on the default public endpoint; task 4.4's rebuild-to-height fallback stays documented as resilience against future pruning changes.

(i) **Budget decision**: Phase 0 spent ~0.97 wmantraUSD; ~9.0 remains, ample through Phases 1-3 including demo-scale anchoring. Tranche-1 bulk load at measured gas (realistic citation records ~96-155k gas each) ~= 1.2-1.6k wmantraUSD. DECISION: tranche 1 does NOT proceed on the current balance; before the Phase 2 load session, top up roughly 2,000 wmantraUSD via the DuKong bridge flow (nvnm-tutorial/README.md) and settle the multi-key loading strategy.

## 2026-06-11: Normalizer behavior pinned against the eyecite stack (tasks 1.2/1.3)
Measured against eyecite 2.7.6 and compensated for in nvnm_cite.normalizer:
- resolve_citations silently DROPS unresolvable short forms (orphan Id./supra/short cites). The normalizer re-reports them as UNRESOLVED occurrences; a dangling Id. must stay visible to the verifier.
- Bare U.S. and S. Ct. cites get court='scotus' from eyecite; bare L. Ed./L. Ed. 2d do NOT (court=None). The us-scotus mapping therefore uses the explicit edition set {U.S., S. Ct., L. Ed., L. Ed. 2d}. All four carry reporters-db cite_type='federal', so cite_type cannot discriminate.
- reporters-db cite_type='scotus_early' is a grab bag (includes 'Bee', "Oliver's Forms") and 'Cranch' is also a D.C. reporter: bare early nominatives ("1 Cranch 137") return AMBIGUOUS_JURISDICTION per never-guess; "5 U.S. (1 Cranch) 137" maps to us-scotus via the U.S. edition.
- eyecite raises on empty input (guarded in normalize()); plaintiff/defendant can come back '' (normalized to None); metadata.year can bleed between citations in tangled text (treated as informational only, never part of keys).
- Normalizer-level dispositions: OK | AMBIGUOUS_JURISDICTION | UNRESOLVED, distinct from the verifier's five-status enum; AMBIGUOUS_JURISDICTION maps 1:1, UNRESOLVED covers occurrences with no canonical key (orphan short forms, pending-publication cites).

## 2026-06-11: CourtListener bulk snapshot 2026-03-31; the COPY dialect is backslash-escaped (silent-desync hazard)
Snapshot: latest available (citations 127 MB / opinion-clusters 2.45 GB / dockets 4.98 GB bz2, from storage.courtlistener.com/bulk-data/). MEASURED dialect: unquoted header row; every non-NULL value double-quoted (FORCE_QUOTE *); embedded quotes BACKSLASH-escaped (PostgreSQL ESCAPE '\', NOT csv-style doubling); literal newlines inside quoted values; NULL = bare empty field. Python's default csv dialect does not error on this: it silently DESYNCS at the first embedded quote and shreds subsequent rows (first run "lost" 312 scotus/ca11 dockets and crashed mid-clusters on garbage). Correct reader: csv.reader(f, escapechar="\\", doublequote=False), verified by a uniform 36-field parse over 200k consecutive cluster rows with embedded quotes decoding correctly. The loader also skips-and-counts structurally short rows into corpus meta (malformed_rows) so real dump corruption stays visible. Clean-run results: 70.0M docket rows -> 679,223 kept (scotus+ca11); 589,930 clusters; 1,379,162 citation rows; 0 malformed; 20.6 min wall.
